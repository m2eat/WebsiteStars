# Starts 需求文档

- 状态：草案（根据产品讨论整理，待确认后进入实现）
- 日期：2026-09-22
- 产品名：Starts
- 一句话：把 GitHub 开源项目和技术网页，变成可自动理解、可检索的个人资料库。

---

## 1. 背景与问题

开源项目、技术官网、博客、文档增长很快。现在主要靠：

- GitHub 自带 Stars
- 浏览器自带收藏夹

这两类都只保存「链接 + 标题」，几乎没有：

- 这是什么（简介、类型、技术栈）
- 为什么收藏（场景、笔记）
- 以后怎么找回来（标签、关键词、语义、对话）

结果是 Stars 和收藏夹越积越多，却很难在「想用某个能力」时把当时存过的东西找回来。

已做过一轮独立网站原型（仿 GitHub Stars 页 + 对话 Agent）。结论是：**日常入口不应是另一个网站**。发现项目和阅读文章都发生在浏览器里，复制 URL、跳到独立站再聊天，摩擦太大。

---

## 2. 目标

### 2.1 要达成

1. 在浏览 GitHub 仓库或任意技术网页时，**一键收藏**。
2. 收藏时自动抽取：**简介、分类、标签、关键词**（GitHub 仓库额外包含类型、语言、技术栈等）。
3. 之后能用 **关键词、标签、筛选** 快速找回；自然语言 / 对话查找作为补充。
4. GitHub 仓库和技术文章进入**同一个资料库**，一次搜索能同时命中。
5. 尽量走免费基础设施；模型、向量库、同步方式 **可配置、可关闭**。
6. 没有 AI Key 时仍能收藏和关键词搜索（降级为页面标题 / meta / GitHub topics）。

### 2.2 不做（第一期）

- 做成公开的社交书签或内容社区
- 替代 GitHub 本身（不仿仓库页、不重做 GitHub UI）
- 全网爬虫、未打开页面的批量抓站
- PDF / 视频 / 播客的完整解析（可后做）
- 团队协作、权限、多租户 SaaS
- 把对话式 Agent 当作唯一首页

---

## 3. 用户与场景

**用户：** 个人开发者，Stars 和网页收藏很多，需要按「能力 / 场景」找回，而不是按网站名。

**典型场景：**

| 场景 | 期望 |
|---|---|
| 在 GitHub 看到一个 CLI 工具 | 点一下即收藏，后台读 README，生成中文简介和标签 |
| 在读一篇 Cloudflare / RAG 教程 | 一键收藏当前页，抽出分类和关键词 |
| 三个月后想找「能在 Workers 上跑的 SQLite」 | 关键词或一句话搜，仓库和文章一起出现 |
| 想不起来名字，只记得「那个终端 UI」 | 用对话补充检索 |
| 不想付费、想换模型 | 设置里换 Key / 关掉 AI |

## 4. 产品形态

**主入口：浏览器扩展（Chrome 优先）。**

- GitHub 仓库页、Stars 页：收藏按钮
- 任意网页：工具栏按钮、右键「收藏到 Starts」
- 弹出层 / 侧栏：搜索、标签、笔记、筛选
- 可选划词：把「为什么收藏」一并保存

**辅入口：很薄的后端 + 可选 Web 后台。**

- 后端负责（可关）：README/正文分析、embedding、跨设备同步
- Web 仅用于大屏浏览、批量导入已有 Stars，**不是**日常仿 GitHub 的主界面

**交互原则：**

- 收藏：当前页完成，不离开 GitHub / 文章
- 检索：默认关键词 + 标签；对话是附加能力
- 失败可降级：AI 不可用时仍能存、能搜

## 5. 功能需求

### 5.1 收藏 GitHub 仓库

- 支持仓库页一键收藏；也允许粘贴 `owner/repo` 或 URL（后台 / 设置里批量用）
- 通过 GitHub API 拉取：描述、language、topics、license、stars、README
- 自动抽取：简介、类型（库 / 框架 / CLI / 模板等）、标签、技术栈、关键词、适用场景
- 可写私人笔记
- 可刷新：重新拉 README 并再分析
- 去重：同一 `owner/repo` 更新而非重复插入
- 可选：同步账号下已有 Stars（限速、可中断）

### 5.2 收藏网页（文章、官网、文档）

- 任意 http(s) 页面一键收藏
- **在当前页 DOM 提取正文**（不依赖服务器去抓，避免登录墙 / 反爬）
- 提取：标题、canonical URL、站点名、作者 / 发布时间（有则用）、正文摘要、Open Graph / meta
- 自动抽取：简介、分类、标签、关键词
- 支持保存用户划选的片段，作为「为什么收藏」
- 去重：按 canonical URL（去掉追踪参数）
- 正文过长时：简介只用前 N 字或当前章节；全文可切块供日后检索
- 抽正文失败时：降级为标题 + meta + 划词，仍允许保存

第一期不要求：PDF、付费墙突破、视频字幕。

### 5.3 统一资料库

每条收藏是同一类「条目」，用来源区分：

- `github`：开源仓库
- `article`：文章 / 博客
- `docs`：文档站（能识别则标，否则归入 article）

共同字段至少包括：URL、标题、简介、分类、标签、关键词、笔记、创建/更新时间、分析引擎。

GitHub 额外字段：owner、repo、language、license、stars、类型、技术栈等。

网页额外字段：domain、author、publishedAt、excerpt / 正文。

### 5.4 检索

必须：

- 关键词（标题、简介、标签、笔记、正文摘录）
- 筛选：来源（仓库 / 网页）、语言、分类、标签
- 排序：最近收藏、名称；仓库可按 stars

应当：

- 语义检索（向量，可关）
- 混合检索（关键词 + 语义）

可以后做：

- 对话式查找（多轮：先广再窄，「只要 TypeScript」）
- 对话只基于用户自己的收藏，禁止编造未收藏条目

### 5.5 展示与管理

- 列表：标题、来源图标、简介、标签、时间
- 详情：简介（标明是否 AI 生成）、原文/README、标签、笔记、相关条目
- 改标签、改分类、改笔记
- 删除 / 取消收藏
- GitHub 条目可跳转仓库；网页条目打开原链接

### 5.6 自定义（必须可配）

| 项 | 说明 |
|---|---|
| AI 提供方 | Workers AI / Gemini / 兼容 OpenAI 的端点 / 关闭 AI |
| 向量库 | Cloudflare Vectorize / 本地 / 关闭语义搜 |
| 结构化存储 | 仅浏览器本地 / D1 / Turso / 其他可插拔后端 |
| 抽取提示词 | 简介语气、中英文、标签风格 |
| 字段 | 默认字段 + 用户自定义字段 |
| 分组 | 收藏夹 / 列表（工作、学习、待看） |
| 同步 | 仅本机 / 云同步（可选） |

没有 Key、关闭 AI 时：GitHub 用官方 description + topics；网页用 title + meta。产品仍完整可用。

### 5.7 账号与权限

- 第一期：单用户个人工具
- GitHub：用户自己的 Token / OAuth，只读公开仓库即可；私有仓库后做
- 网页：只处理用户主动打开并点击收藏的页面，不后台爬网

## 6. AI 行为

触发时机：用户主动收藏或点击「重新分析」，禁止偷偷扫描整机历史。

对 GitHub README / 网页正文，产出结构化结果（示例）：

- summary：1–2 句说明「是什么、能干什么」
- category / type：分类或仓库类型
- tags：3–8 个短标签
- keywords：便于检索的词
- 可选：stack、use_cases、audience

约束：

- 不编造页面/README 中不存在的能力
- 抽取失败不阻断收藏
- 界面上区分「AI 简介」和「原文描述」
- 对话检索不得推荐用户没收藏过的项目

---

## 7. 非功能需求

- **免费优先：** 个人用量应能跑在 Cloudflare / 浏览器本地 / Gemini 免费档等组合上
- **本地优先：** 核心数据可只放在浏览器；云是增强不是前提
- **性能：** 收藏点击后应立即有反馈；AI 分析可异步，并显示简短状态
- **隐私：** 正文和笔记默认私有；第三方模型按用户自己的 Key 发送
- **稳定：** GitHub 页面改版不应让「收藏」完全不可用（仓库 URL 解析作为兜底）
- **扩展：** Chrome 先行；Firefox 不作为第一期必达

---

## 8. 成功标准

第一期可认为达标，如果：

1. 在 GitHub 仓库页和任意文章页都能一键收藏，无需复制链接到另一个网站
2. 大多数收藏会带上可用的简介和标签（AI 或降级规则）
3. 用关键词 / 标签能在混合库（仓库 + 网页）里找回条目
4. 关掉 AI 和向量后，收藏与关键词搜索仍可用
5. 能在设置里更换或关闭模型，而不改代码

---

## 9. 分期

### P0 — 能每天用

- Chrome 扩展：GitHub 一键收藏、网页一键收藏
- 自动抽取简介 / 分类 / 标签 / 关键词（可降级）
- 弹窗：关键词搜索、标签筛选、来源筛选、笔记
- 本地存储；可选 Cloudflare 分析后端

### P1 — 更好找、可换后端

- 语义检索、相似条目
- 已有 Stars 批量导入
- 设置：模型、提示词、向量库、同步
- 自定义分组

### P2 — 对话与增强

- 多轮对话查找（追问、收窄）
- 文档站长文切块检索
- Firefox、私有仓库、PDF

---

## 10. 与现有原型的关系

仓库里已有 Cloudflare Workers + React 网站原型，能力包括：GitHub 解析、Workers AI 分析、D1、FTS、Vectorize、对话检索。

**保留：** 分析 / 入库 / 检索 API，作为可选云端引擎。

**不再作为日常 UI：** 仿 GitHub Stars 的独立站、以 Agent 聊天为首页。

独立站可降级为「设置、批量导入、大屏列表」。
