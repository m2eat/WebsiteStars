# 对话查询实现

WebsiteStars 的对话查询使用 Vercel AI SDK `ToolLoopAgent`。它在扩展后台调用模型，执行本地只读工具，再把经验证的结果发送给 React 界面。此功能无需新的托管后端。

## 模块边界

| 模块 | 责任 |
| --- | --- |
| `lib/agent.ts` | 框架循环、模型 provider、工具定义、超时/预算、连接探测 |
| `lib/retrieval.ts` | 来源分块投影、关键词/语义融合、多章节读取、小库浏览、引用验证 |
| `lib/content-index.ts` / `lib/chunking.ts` | 可恢复的本地分块与增量向量索引 |
| `lib/embeddings.ts` | 独立兼容 Embedding 接入、维度和响应校验 |
| `lib/query-context.ts` | 追问主题、明确条件与最终结果序号排除 |
| `lib/query-instructions.ts` | 召回、核对、筛选与最终输出的系统提示词 |
| `lib/chat-store.ts` | 会话、消息、运行记录、事务与后台恢复 |
| `lib/chat-server.ts` | 后台 Port 协议、运行状态、停止、设置变化与流式输出 |
| `lib/chat-client.ts` | AI SDK React `ChatTransport` 与扩展消息桥接 |
| `ui/Markdown.tsx` | 安全渲染聊天及 README Markdown，隔离表格/代码滚动与外部资源 |
| `lib/streaming-answer.ts` | 增量解析最终答案字符串及转义，不回放已有文本 |
| `ui/ChatPanel.tsx` | `useChat`、本地消息订阅、草稿、历史、进度与引用展示 |
| `ui/OptionsApp.tsx` | 独立查询开关、连接配置、模型列表、超时与显式工具能力测试 |
| `lib/models.ts` | 读取模型目录、限量解析、错误处理，不执行模型推理 |
| `lib/model-fetch.ts` / `entrypoints/model-network/` | 受信任 offscreen 页面与独立 Worker 网络代理、流背压、取消、有限保活 |
| `ui/beautiful/primitives.tsx` | Beautiful UI 开源组件源码适配，使用真实状态及受检索校验的来源 |

界面读取本地会话为权威状态；客户端传给后台的只有会话标识和新问题，不接受客户端构造的任意助手历史。关闭或切换页面不自动再次调用模型。

## 单轮执行

1. 校验查询开关、输入、会话状态，原子保存问题及本轮运行意图。
2. 从本地历史提取最多六轮问题，重新验证旧引用；不重放过时的自由回答或私有 reasoning。条件型追问将近期主题合入实际语义查询。按上轮最终结果的顺序理解“第一个/第二个”；删除或受限位置以空位保留，不把序号移到其他收藏，也不外发失效编号。
3. 小资料库先提供完整短概况；`ToolLoopAgent` 按用途召回候选，需要细节时用 `read_items` 批量核对 2–6 条或 `read_item` 读取单条。相同搜索和片段读取在本轮复用，但每次复用仍检查来源和设置，输出仍计入上下文预算。只有难以区分的复杂候选才需要 `rerank_candidates`。
4. `present_results` 提交答案与最终选中的有序结果，原文编号由本地解析。最终提交重新验证语言、来源和排除条件，引用必须来自本轮已暴露的来源，且收藏仍存在、版本有效、允许发送。卡片只读取已完成消息的最终 citations；搜索、读取、重排、失败和旧运行记录都不能直接生成卡片。
5. 从框架的工具输入增量中提取顶层 `present_results.answer`，只追加稳定的答案前缀并渲染 Markdown，不混入中间说明或工具 JSON。完成后校验并保存最终回答、引用和运行状态。工具提供原文编号供模型选择，引用不合格时在现有预算内允许一次纠正，修正答案在核验后替换草稿。无匹配返回空结果；未完成、失败和停止时保留运行记录和重试操作，不将候选伪装成输出结果。

工具没有修改收藏、执行代码或外部网络搜索的能力。模型不得把网页或 README 中的指令当作系统指令。工具调用必须经过 Schema 和访问规则，不能凭任意 ID 读取全库。

系统提示词、工具说明、重排与引用纠正指令统一使用英文。输出优先遵循用户明确指定的语言，否则按当前提问语言回答；短追问沿用对话语言。回答、澄清问题和推荐理由遵循同一规则，名称与证据原文保持不变。界面语言仍独立跟随浏览器。英文指令不代表已证明所有模型的检索质量更好。

## 检索与扩展

独立 `RetrievalService` 封装检索。当前实现使用持久章节分块、MiniSearch 中文/技术词检索、多组 OR 召回与向量余弦排序融合。语义查询需要独立启用 Embedding，未配置或服务失败时走关键词并显示真实模式。模型可将“终端交互界面”改写为 `terminal UI`，也可直接使用多语言向量召回英文来源。每条最多提供三个相关章节。

向量模型可使用远程或本机兼容服务，浏览器内置模型尚未集成。接口保留后续替换向量引擎的空间。来源不足、向量模型不适合该语言或相关条件不在来源中时仍可能无法召回。固定语料与真实本地模型评测见 `docs/retrieval-upgrade.md`。

## 数据范围

默认不调用模型。发送问题时会传递用户问题及有限的候选来源信息，排除私人笔记、独立划词和人工覆盖字段。当前条目只有单个标题字段，因此手动编辑过的标题也可能作为标题发送。禁止域名、已知私有与未确认公开的 GitHub 仓库不参与模型检索。

会话、草稿与执行记录在本机保存；不包含在现有收藏 JSON 备份里。默认关闭遥测，不持久化请求密钥或模型私有 reasoning。运行记录展示工具、候选 ID、耗时、模型和可用 token 数。

## 限制与中断

每轮最多 6 个主模型步骤、12 次工具调用、20 个正文候选。第 5 步起或工具预算只剩 2 次时仅开放最终提交工具，为提交及一次引用纠正保留机会；纠正阶段也只开放最终提交。额外候选模型重排最多两次，片段最多 1200 字符，累计工具输出最多 32000 字符。模型步骤/首块响应默认 180 秒，可设 30–1800 秒；整轮默认 900 秒，可设 60–3600 秒并且不短于单步。配置统一应用到 Agent、连接探测和模型 fetch，摘要分析也使用单次模型时限。SDK 自动重试关闭。

通过 offscreen 页面的独立 Worker 发起模型网络请求，避免 MV3 service worker 的 fetch 首响应短等待限制。内部 Port 校验扩展 ID、文档路径与发送方，不开放给网页内容脚本。请求在途时每 20 秒发送通信心跳，完成/取消后停止；后台断开会终止网络 Worker。响应按消费端需求读取，避免把完整流无限缓存在内存。分析任务租约比其模型时限长 45 秒，避免慢请求尚在进行时被重复领取。

Chrome Manifest V3 后台可能终止。恢复时将未完成查询标记为中断并提供手动重试；不能假装原网络流仍存在或自动重放可能已计费的请求。停止、设置变更与删除会话必须使迟到结果失效。

## 验证与评测

- `tests/agent.test.ts`：实际 ToolLoopAgent 与模拟标准 OpenAI SSE，验证多步工具、循环预算、错误、取消、Workers AI 地址与能力探测。
- `tests/retrieval.test.ts`：召回、技术词、过滤、相关片段、引用及字段隐私。
- `tests/chat-store.test.ts`：并发、运行状态、迁移、恢复与删除。
- `tests/chat-runtime.test.ts`：最终提交与设置变更互斥、引用状态校验、延迟停止只命中对应请求、新配置运行不被旧配置清理中止，以及拒绝网页内容脚本连接。
- `tests/browser/agent.spec.ts`：临时 Chromium 加载真实扩展，连接本地标准工具调用/SSE服务，交互完成设置、提问、追问、引用、停止、重试、后台重启、设置取消及会话删除。

这些确定性测试验证应用与框架协议、状态一致性和隐私边界，不等同于真实模型的搜索质量评测。替换模型或检索策略时，应另外使用固定收藏集及模糊描述案例，比较命中结果、错误引用、请求数和耗时；无用户凭证时不执行付费模型质量测试。
